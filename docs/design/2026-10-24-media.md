## 1. Meaning, from the pinned standards only

A photograph, letter or testimony is a Source (`rico:Record`). Its held or linked file is an
instantiation (`rico:Instantiation`), linked to the Source by `rico:isOrWasInstantiationOf`.
`Source.subjects` uses `rico:hasOrHadSubject`, from RecordResource to Thing. It describes what a
record is about; it is not a list of everyone visible in a particular scan.

The pinned `standards/rico-1.1-axioms.json` explicitly gives `rico:hasRepresentationType` domain
Instantiation and range RepresentationType. `kind` now uses that property with **local** concepts
`pc:media_image`, `pc:media_audio`, `pc:media_video`, `pc:media_document`, typed RepresentationType
in `vocabulary/media.profile.ttl`. They are not RiC-O's own controlled values. `hasContentOfType`
belongs to Record/RecordPart and is not used on the medium. Access/use terms use
`rico:conditionsOfAccess` / `rico:conditionsOfUse`; width/height use the pinned properties of
those names. Duration, pixel rectangles, review/clearance, consent, storage and delivery are
local with their reasons in `vocabulary/media.json`.

`Source.made_by` is a closed local classification: `family | studio | institution | perpetrator |
unknown`. It is not an Agent and therefore does not map to `rico:hasCreator`. Existing sources
may omit it; classification is part of the owner's media review. Perpetrator-made camp
registration photographs, prisoner cards and transport lists remain worded citations linking
to their holders. Steps refuses their media on a person's page, following `derived_from` too,
so copying a record does not remove its origin. Citations and sources themselves remain valid.

## 2. The shared contract

Zod and Pydantic are twins. Objects are closed, dates are calendar days, pixel coordinates are
safe integers, and every cross-reference resolves before writing. Main fields:

| Field | Meaning and checks | Public |
|---|---|---|
| `id`, `source_id`, `kind` | Stable medium id, original record, image/audio/video/document | yes |
| `caption {text, lang, reviewed}` | Our words from recorded facts; BCP 47 language required | yes |
| `alt {text, lang, reviewed}` | Visible description, required for images and documents | yes |
| `inscription {text, lang, reviewed}` | The object's own words, in their own language | yes |
| `transcript {text, lang, reviewed}` | Full text required for documents, separate from short alt | yes |
| `family_words {source_id, page, quote, quote_language}` | A Citation subset: exact family words and their recorded page/part; no private note/locator | yes |
| `depicted [{person_id, region, identified_by}]` | Every visible person: id or **explicit null**; `identified_by` only family/record/inscription | yes |
| `shows_unidentified` | Required boolean; must be true when a depicted id is null | yes |
| `width`, `height`, `duration` | Oriented master pixels (both dimensions together), or seconds | yes |
| `credit` | Required, the holder's/family's chosen words, preserved verbatim | yes |
| `conditions_of_access`, `conditions_of_use` | The holder's wording, separately recorded and reviewed for publication | yes |
| `rights` | Exact URI from `standards/media-rights.json`; omitted means CNE, Copyright Not Evaluated | yes |
| `cleared`, any `reviewed` | `{on, role}`, role only `owner | project`; never a contributor name | yes |
| `withdrawn {on, reason}` | Retained state; reason only family/holder/error, no private explanation | yes |
| `link` | Plain audio/video holder-page link, constrained to its registered host | yes |
| `derived [{url, width, height, process}]` | Hash-only WebP names, actual dimensions, `process: resize` only | yes |
| `master {bucket, key, sha256, mime, bytes, checked}` | Separate private bucket name, digest key; optional `checked {on, sha256}` must match the master digest | **no** |
| `consent {basis, granted_by, scope, ref, withdrawn_on}` | Permission evidence, separate from the owner's clearance | **no** |

`region` is `{x,y,w,h}` in **oriented master pixels**, with nonnegative x/y and positive w/h,
contained in the master. It serializes as IIIF's `x,y,w,h` region later; it is neither a percentage
nor a CSS rectangle. `portrait {media_id, region, reviewed}` is on the person, needs a cleared
image depicting that person and a reviewed caption. This ticket models the selection; generating
a cropped face file and the site's “see it whole” link remain page-side/future delivery work.
All derivatives here preserve the full frame and permit only resize/re-encoding, no upscaling.

Consent basis is `institution-terms | holder-licence | family-permission | public-domain |
owner-family-papers`. `scope` is `{use: site | site+download, person_ids: [...], unidentified:
boolean}`. `granted_by` is a role (`owner`, `family`, `holder`, `institution`), never a
person's name: no living person's name is kept in any repository, private files included. Explicit ids say whose permission the private `ref` documents; the giver may be a
representative whose authority the owner checks. Every living sitter requires `family-permission`
covering their id. Ownership or copyright terms are not consent. `withdrawn_on` requires the
medium's withdrawal state; it cannot silently leave cleared URLs active. Neither `granted_by`
nor `ref`, the scope or the bucket/fixity log leaves `publicMedia` / `public_media`.

The rights list is pinned from the official RightsStatements and Creative Commons pages listed
in `standards/media-rights.json`: twelve RightsStatements **http** vocabulary URIs, six CC
international 4.0 licences and CC0/PDM 1.0. HTML `/page/` addresses, invented paths, RightsStatements
https aliases and unlisted CC versions are refused. Older CC versions need a reviewed addition,
not a permissive URL pattern. `InC-OW-EU` is refused on photographs because its stated scope
excludes photography. Copyright Not Evaluated says nothing about permission to publish.
`vocabulary/generate.py` generates `zod/media-rights.table.ts` from that pinned list, and its
drift check runs in `bin/verify`. The new Zod files import only within `zod/`, so the site's
vendored tree stays self-contained without copying `standards/` into its application.

## 3. Refusals and the parts a person must check

Steps' existing living-presumption policy is recorded in decision 94 (14 October revision),
and `site_people.py` preserves its evidence as structured facts. The executable general
presumption is on the site (`privacy/presumption.ts`), not previously in steps. The new
`site_media_policy.py` applies its death evidence, birth-at-least-110-years and print-at-least-85-years
rules to every depicted person, including preserved facts and vouched relatives' deaths.
A hedged fate does not establish death. Permission to show a person's text record (`shown`) is
not permission for a photograph; the private consent must name the sitter. No face recognition,
computer naming, inferred identity or age guessed from an image participates.

Every non-null sitter id must resolve to a person. An unidentified picture after 1945 needs both clearance
and consent whose scope explicitly covers unidentified people. Undated pictures take that same
conservative path; a range uses its later endpoint. For private sources, derivation also needs
active permission evidence. The checks run before opening a master, and again on the writer's
final record, including predeclared served URLs. Refusal leaves installed files untouched.
A withdrawn tombstone is retained without derived URLs or holder links and without rerunning
consent requirements for publication that has ceased.

Alt checks enforce at most 150 Unicode code points, difference from the caption, known names
only from `depicted`, and obvious English hindsight/interpretation phrases (including “Image of”,
“Holocaust victim”, “before the war”, “happy”, “doomed”). These are limited checks, not a proof
that arbitrary language describes only visible things. The owner reviews unidentified names,
all languages, relations, emotions, dates, and any inference. No model identifies a sitter.
Inscription and transcript reviews stay separate from our caption review. Private family quotes
need the quoted source's `quotes_cleared` before the writer accepts `family_words`.

The site's implementation must render the visible caption's fixed “written by computer” label
until reviewed, and append its translated fixed label to an unreviewed portrait's alt; that
suffix is added at rendering, outside the stored 150-character description. The model carries
the language and review state, not hard-coded English presentation labels. Caption review is
required for a portrait; alt review is independent. The site licence must say: **the project's
CC BY data licence does not cover the pictures; each picture has its own credit and rights.**
The credit is intended for IIIF `requiredStatement` when IIIF is implemented; no unpinned IIIF
ontology assertion is introduced here.

## 4. Local files and one width list

`zod/media-widths.json` is the one authored list. Zod exports it as `MEDIA_WIDTHS`; Pydantic reads
that file to construct its derivative URL grammar. Steps' `site_shapes` exporter writes it,
the rights table and language grammar to `schemas/site/media-policy.json`. `site_pictures.SMALLER`
and the media writer read that export. After the schema review is committed, `site_shapes refresh`
records the clean commit and regenerates the consumer copies. No dirty work is described as a
clean pin. The site can `import { MEDIA_WIDTHS } from '$lib/schemas'` through its existing schema
re-export (or import `src/vendor/pruzhany-schema/zod/media-widths.json`); derive REMOTE_WIDTHS and
its thumbnail from it, rather than maintaining another literal list. No site file was edited.

`derive(..., shared=record)` verifies original bytes/MIME and single-frame status, applies
`ImageOps.exif_transpose`, converts embedded ICC profiles through `ImageCms` to sRGB, and only
then removes EXIF, XMP, ICC and other metadata. Untagged RGB/grayscale/palette is interpreted as
sRGB; untagged CMYK/LAB and invalid profiles fail instead of guessing. The master stays unchanged.
The successful hash check is recorded in `master.checked`. Each derivative is
`/media/<full-sha256-of-derived-bytes>-w<nominal-width>.webp`, with its actual dimensions.
Neither a person's name nor a medium id appears in the filename. Orientation and colour
conversion preserve the original appearance; there is no colouring, restoration, framing or
upscaling. Tests create EXIF/GPS/maker-note/XMP fixtures and a LAB-profile image locally and
check orientation, colour, unchanged masters and the absence of private WebP RIFF chunks.

Pillow API consulted: [ImageCms](https://pillow.readthedocs.io/en/stable/reference/ImageCms.html).
No contributed file, API service, paid call or bucket is used by these tests.

## 5. Owner-machine bucket and withdrawal plan (not executed)

1. Create a dedicated private masters bucket, distinct from the public picture bucket. Its
   name exists only in `master.bucket` and private owner configuration. Attach **no domain**,
   keep **r2.dev disabled**, and do not expose it via Workers, image transformations, IIIF or
   signed delivery links. The schema rejects the known public bucket name but cannot inspect
   infrastructure permissions.
2. Keep a bucket-scoped read/write token on the owner's machine, never in source, CI or a cloud
   session. Use a separate token scoped only to the public derivatives bucket for publication.
3. Keep a second independent full-quality copy. Verify both copies against SHA-256 on ingest
   and periodically, recording successful checks as `master.checked {on, sha256}`; never replace
   the expected digest to hide a mismatch. Record backup/check failures privately.
4. Before first publication, create a private sentinel on the owner's machine. A CI check
   with no credentials must see **404** for its key through every public picture route, including
   `pictures.pruzhanychronicles.org`. Check the bucket's disabled public endpoints too. A redirect,
   200, or authentication challenge instead of the required anonymous 404 fails the check.
   CI needs neither the bucket token nor a real photograph. Repeat on configuration changes.
5. Serve media with `Cache-Control: public, max-age=604800` (one browser week), **no `immutable`**.
   A purge cannot erase copies already downloaded or cached in a browser.
6. For withdrawal, retain id, source, citation and the dated closed reason. Before removing its
   URLs from the active record, keep a private manifest of the old addresses; delete those public
   objects, purge each CDN URL, rebuild/deploy pages and data, and verify anonymous requests no
   longer serve them. Inventory the public media prefix against active cleared manifests so
   orphaned files are caught. The page says removed at the family's or holder's request, as
   appropriate; citations still resolve. Retain a master only with the family's permission.

No storage setup, upload, purge, browser-header change or site publication is claimed by this
model ticket. AVIF, separate print/copy instantiations, EDTF, indexing/CSP, gallery UI, recording
alternatives and IIIF stay outside the requested three Should items.
